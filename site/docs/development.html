Development

Development

go test ./...          # unit tests; node scripts run under dash, bash and busybox if present
go vet ./...

The integration tests in test/integration build the binary and run it against real WireGuard interfaces in network namespaces. They change the machine they run on, so they need root (or passwordless sudo) and an explicit opt-in:

WGLINK_INTEGRATION=1 go test -tags integration -v ./test/integration/

CI runs them on every pull request, with the runner itself as a systemd node.

To release, add the version's section to CHANGELOG.md, then push a vX.Y.Z tag, or run the release workflow from the Actions tab with the version (and, optionally, a commit). Either way it tests, builds the archives and packages with scripts/release.sh, and publishes them. The packages come from nfpm and packaging/nfpm.yaml; CI builds them on every pull request and installs them on Debian and Fedora. To redo a release, run the workflow with replace ticked. It removes the old release and tag only after the new build passes.

The website is plain HTML and CSS in site/. Its docs pages are made from this README and the commands' help by go -C scripts/docgen run ., and CI fails if they're out of date. The pages workflow publishes the site with GitHub Pages whenever it changes on main.

Package Role
cmd/wglink entry point
internal/cli commands, flags and output
internal/config wglink.yaml: parsing, validation and comment-preserving edits
internal/edit adding nodes and connecting them, shared by the commands and the dashboard
internal/ipam subnet, port and address selection
internal/engine plan, apply and status
internal/node the embedded scripts and their parsers
internal/runner local, SSH, exec, pct and guest agent transports
internal/wgconf rendering, parsing and comparing wg-quick configs
internal/state wglink.state.json
internal/tui the wglink ui dashboard
