Describe nodes and networks

wglink connect

Join nodes in a full mesh, or with --hub, all through one of them. Without
--name, two nodes get a network named after them and more get net1, net2, and
so on. Addresses are automatic unless pinned with --ip, as a host part
(nas=.10) or a full address (nas=10.99.0.10).

Usage:
  wglink connect NODE NODE [NODE...] [flags]

Examples:
  wglink connect pve1 pve2
  wglink connect pve1 nas ct101 --name lab
  wglink connect vps laptop phone --name road --hub vps
  wglink connect nas pve1 --name backup --subnet 172.30.5.0/24 --ip nas=.10

Flags:
  -h, --help                   help for connect
      --hub string             member the others connect through, instead of all to all
      --ip stringArray         pin an address: NODE=.N, NODE=.N.N or NODE=ADDRESS (repeatable)
      --ipv6 string[="auto"]   add IPv6: alone for a random unique local /64, =PREFIX for a fixed one, or =off
      --keepalive string       keepalive interval in seconds for every member (0 is off)
      --mtu string             interface MTU (default: wg-quick decides)
      --name string            network name, at most 12 characters
      --port string            UDP listen port on every member (default: first free from 51820)
      --psk                    give each pair of peers a preshared key as well
      --subnet string          IPv4 subnet, e.g. 10.99.0.0/24 (default: picked from the pool)

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink discover

Ask a Proxmox VE host, already a node, for its containers and VMs, with the
addresses of the running ones. Containers are reached with pct and VMs with
the QEMU guest agent, both through the host, so guests need no SSH.

With --add, every running guest that isn't a node yet becomes one, named after
the guest and dialed at its address. Then add them to a network.

Usage:
  wglink discover HOST [flags]

Examples:
  wglink discover pve1
  wglink discover pve1 --add
  wglink net join lab nas web

Flags:
      --add    add every running guest that isn't a node yet
  -h, --help   help for discover

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink node add

Add a machine, or a device such as a phone

Usage:
  wglink node add NAME (--ssh DEST | --local | --exec CMD | --pct VMID --via HOST | --qm VMID --via HOST | --manual) [flags]

Examples:
  wglink node add pve1 --ssh root@192.168.1.10
  wglink node add nas --ssh admin@nas.lan --sudo
  wglink node add pi --ssh pi-garage                 # a Host in ~/.ssh/config
  wglink node add ct101 --pct 101 --via pve1 --endpoint 192.168.1.101
  wglink node add vm200 --qm 200 --via pve1 --endpoint 192.168.1.200
  wglink node add web --exec "docker exec -i web" --endpoint 172.17.0.2
  wglink node add laptop --local --endpoint 192.168.1.50
  wglink node add phone --manual --keepalive 25     # set up with wglink export

Flags:
      --endpoint string   address peers dial: host, host:port or "none" (default for ssh: the ssh host)
      --exec string       reach it through a local command, e.g. "docker exec -i web"
  -h, --help              help for add
      --keepalive int     send keepalives every N seconds (for nodes behind NAT)
      --local             it is the machine wglink runs on
      --manual            a device wglink can't reach, such as a phone; its config comes from wglink export
      --no-check          don't connect to check the node
      --pct int           a Proxmox container ID, reached with pct exec through --via
      --pubkey string     the public key a --manual device already has (default: made by wglink export)
      --qm int            a Proxmox VM ID, reached with its QEMU guest agent through --via
      --service string    how tunnels start at boot: auto, systemd or none
      --ssh string        reach it over SSH: user@host, ssh://user@host:port or a ~/.ssh/config alias
      --sudo              become root with sudo -n (ssh and local)
      --via string        the Proxmox host node for --pct or --qm

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink routes

Set the subnets behind a member, such as its LAN, that the network's other
members reach through it. With no subnets, the member routes nothing.

The member needs IP forwarding on, and hosts on those subnets need a route
back to the network through it.

Usage:
  wglink routes NETWORK NODE [SUBNET...] [flags]

Examples:
  wglink routes lab nas 192.168.50.0/24
  wglink routes lab nas              # route nothing

Flags:
  -h, --help   help for routes

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

Change and inspect nodes

wglink apply

Show the plan, ask for confirmation, then change the nodes: remove interfaces
that are no longer wanted, create missing keys on their own nodes, and write
configs one node at a time. It stops at the first failure; running it again
picks up where it stopped.

Each change to an SSH node is confirmed over a new SSH connection. If that
fails, for example because the change cut off the route wglink uses, the
node puts its previous config back after a minute. This needs systemd on the
node; --no-revert turns it off.

Usage:
  wglink apply [flags]

Flags:
      --adopt          replace configs wglink didn't write
  -h, --help           help for apply
      --net strings    only these networks (repeatable)
      --no-revert      don't have SSH nodes undo a change that wglink can't confirm
      --node strings   only change these nodes (repeatable)
  -y, --yes            don't ask for confirmation

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink export

Print the wg-quick config for a manual node: a device wglink can't reach,
such as a phone. The first export makes the device's key pair. The private
key goes into the printed config and is kept nowhere else; the public key is
saved in wglink.yaml. Later exports leave a placeholder for the private key,
unless --new-key replaces the pair.

In a network with preshared keys, every export makes new ones: the peers
wglink can reach store theirs, and the config carries the device's.

Then run "wglink apply" so the other members add the device as a peer.
"wglink plan" says when a device's config has changed and needs exporting
again.

Usage:
  wglink export NETWORK NODE [flags]

Examples:
  wglink node add phone --manual --keepalive 25
  wglink net join lab phone
  wglink export lab phone -o phone.conf
  qrencode -t ansiutf8 < phone.conf    # scan with the WireGuard app
  wglink apply

Flags:
  -h, --help            help for export
      --new-key         make a new key pair; the device needs the new config
  -o, --output string   write the config to this file (mode 0600) instead of stdout

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

Global Flags:

wglink rotate

Make new keys for some or all of a network's members, on the members
themselves, and give the new public keys to their peers. Each member loads its
new key live. Manual nodes get new keys with "wglink export --new-key".

Usage:
  wglink rotate NETWORK [NODE...] [flags]

Examples:
  wglink rotate lab            # every member that wglink reaches
  wglink rotate lab nas

Flags:
  -h, --help        help for rotate
      --no-revert   don't have SSH nodes undo a change that wglink can't confirm
  -y, --yes         don't ask for confirmation

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink state rebuild

Read each member's config and put wglink.state.json back together: every
network's subnet and port, and every member's address, public key and config
hash. Use it when the state file is lost or out of date. The old file is kept
as wglink.state.json.bak.

Members wglink can't read, such as manual or unreachable ones, are taken from
their peers' configs, and manual nodes are assumed to have their current
config.

Usage:
  wglink state rebuild [flags]

Flags:
  -h, --help          help for rebuild
      --net strings   only these networks (repeatable)

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)

wglink status

Ask every member for its live WireGuard state and show each pair's link.
A link is ok after a handshake in the last 3 minutes or a ping reply through
the tunnel. wglink pings each peer's tunnel address unless --no-ping is set.

With --local, or when no wglink.yaml is found, status shows this machine's
WireGuard interfaces instead, naming peers from the configs wglink wrote.

Usage:
  wglink status [flags]

Examples:
  wglink status
  wglink status --net lab --json
  wglink status --exit-code     # for scripts: 2 unless every link is ok
  sudo wglink status --local    # on a node, without wglink.yaml

Flags:
      --exit-code     exit with status 2 unless every link is ok
  -h, --help          help for status
      --json          print JSON
      --local         show this machine's interfaces instead of wglink.yaml's networks
      --net strings   only these networks (repeatable)
      --no-ping       judge links by handshakes alone

Global Flags:
      --dir string   directory holding wglink.yaml (default: $WGLINK_DIR, then ., then ~/.config/wglink)
