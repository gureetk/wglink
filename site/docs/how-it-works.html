How it works

  1. Probe. For plan, wglink connects to every node in parallel and runs a read-only script that reports addresses, routes, UDP ports in use, WireGuard interfaces and their configs, with private keys removed.
  2. Resolve. Pinned values come first, then values recorded from earlier runs, then new picks that avoid everything the nodes reported.
  3. Diff. wglink renders each member's wg-quick config and compares it with what's on the node. Peer changes can load live. Address, port and MTU changes need a restart. A config whose hash no longer matches the last apply was edited by hand.
  4. Apply. First, missing keys are created on their nodes with wg genkey. Only public keys come back. Then each config is sent without its private key, and the node inserts the key as it writes the file. The change is loaded with wg syncconf or by restarting wg-quick, through systemd's wg-quick@IFACE where it's available, so tunnels come back after a reboot.
  5. Confirm. Before changing an SSH node, wglink arms a systemd timer there that puts the previous config back. After the change, it opens a new SSH connection and cancels the timer. If the change cut off the route wglink uses, the new connection fails, and a minute later the node undoes the change by itself. --no-revert turns this off.

The scripts are embedded in the binary and fed to sh -s over stdin. They are tested under dash, bash and busybox. Only a few WG_* variables change between runs, and each is validated and quoted.
