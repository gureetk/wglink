Security

  • Private keys stay on their nodes. Each is created with wg genkey on the machine that uses it, stored as /etc/wireguard/IFACE.key with mode 0600, and never printed. The scripts mask keys in everything they report. The integration tests check that no private key appears in wglink's output, inventory or state. The one exception is a manual node: wglink can't run anything there, so wglink export makes its key and writes it into that one config, readable only by you.
  • Keys you can replace. wglink rotate NETWORK [NODE...] makes new keys on the members and hands their peers the new public keys, all loaded live. If a rotation is interrupted, the next plan notices a config or interface still using the old key and loads the new one.
  • Optional preshared keys. With --psk, wglink makes a key for each pair from the operating system's random source and sends it to both members over the same connection as the scripts, on standard input. It never writes them on the controller; nodes report only their hashes. The tests fail if a preshared key shows up in any script's output.
  • No secrets on the controller. The state file holds public keys, addresses, and hashes of configs and preshared keys, with the secrets removed before hashing.
  • No shell on the controller. wglink runs commands as argument lists. Values sent to remote shells are validated and single-quoted.
  • Your SSH setup, unchanged. wglink uses your SSH client in batch mode with your keys, agent and known hosts, and only ever runs sudo -n.
  • Hands off foreign configs. wglink marks the files it writes and won't replace a config without that marker unless you pass --adopt. It keeps the previous file as IFACE.conf.prev.
